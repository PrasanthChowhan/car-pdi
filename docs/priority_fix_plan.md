                                                                                                                                                                                                              
  ### System model                                                                                                                                                                                              
                                                                                                                                                                                                                
  • Client-side Progressive Web App (React + Vite) designed to run fully offline after initial load.                                                                                                            
  • Global state managed via a store ( useInspectionStore.ts  using Zustand) and actively synchronized to IndexedDB using  idb-keyval .                                                                         
  • Inputs originate from the user and the device camera via standard HTML5  <input type="file" capture="environment"> .                                                                                        
  • Image processing (compression/downscaling) occurs in the browser using the Canvas API prior to storage.                                                                                                     
  • PDF reports are constructed dynamically in the DOM and rasterized using  html2canvas  and  jspdf .                                                                                                          
  • Trust Boundaries: Completely local execution; no server interactions beyond initial asset delivery. The primary trust boundaries are between the app and the browser's storage/memory limits.               
                                                                                                                                                                                                                
  ### Critical issues                                                                                                                                                                                           
                                                                                                                                                                                                                
  OOM Crash during Multi-Page PDF Generation                                                                                                                                                                    
                                                                                                                                                                                                                
  • Severity: Critical                                                                                                                                                                                          
  • Evidence: PDF generation logic using  jspdf  +  html2canvas .                                                                                                                                               
  • Impact: The app crashes at the very end of the user journey, destroying the PDF export and frustrating the user after a 30-minute inspection.                                                               
  • Why this fails in production:  html2canvas  works by rendering a target DOM node onto a single  <canvas> . If the summary report contains 20+ photos and spans multiple printed pages, the resulting DOM    
  node will be massive. iOS Safari enforces a strict maximum canvas size. Exceeding this silently crashes the tab or returns a blank image.                                                                     
  • Minimal fix: Do not use  html2canvas  for the entire summary page. Instead, format the PDF programmatically using  jspdf  native text/image methods, adding pages iteratively, or render individual smaller 
  DOM nodes (e.g., one card at a time) and stitch them into the PDF.                                                                                                                                            
  • Confidence: High                                                                                                                                                                                            
                                                                                                                                                                                                                
  iOS Safari Background Tab Eviction during Camera Use                                                                                                                                                          
                                                                                                                                                                                                                
  • Severity: Critical                                                                                                                                                                                          
  • Evidence: Camera Integration via  <input type="file"> .                                                                                                                                                     
  • Impact: User takes a photo, the browser reloads when returning from the camera app, and the current photo + any unsaved state is permanently lost.                                                          
  • Why this fails in production: iOS aggressively manages memory. When the native camera app opens, Safari tabs are frequently suspended or killed. Upon returning, the browser reloads the page. If the state 
  is not fully flushed to IndexedDB before the input triggers, data is lost.                                                                                                                                    
  • Minimal fix: Implement aggressively eager state saving. Maintain an ID in localStorage of the "currently active inspection" to auto-resume on load. Note that mitigating the loss of the in-flight photo is 
  difficult; provide clear UX for users to retake if a crash is detected via a session flag.                                                                                                                    
  • Confidence: High                                                                                                                                                                                            
                                                                                                                                                                                                                
  ### High issues                                                                                                                                                                                               
                                                                                                                                                                                                                
  IndexedDB Quota Exceedance and Silent Failures                                                                                                                                                                
                                                                                                                                                                                                                
  • Severity: High                                                                                                                                                                                              
  • Evidence: State Management & Storage ( useInspectionStore.ts ).                                                                                                                                             
  • Impact: New flags and photos fail to save. If the app reloads, data is missing.                                                                                                                             
  • Why this fails in production: Browsers allocate IDB quotas based on available device storage. Even with compression, 30-40 photos can consume tens of megabytes. If the quota is hit,  idb-keyval 's  set   
  operations will reject. If this promise rejection is unhandled, the UI will appear to accept the photo, but it will vanish on reload.                                                                         
  • Minimal fix: Wrap all IDB write operations in try/catch blocks. If a write fails with a  QuotaExceededError , display an immediate blocking alert requiring the user to generate a PDF and clear data before
  continuing.                                                                                                                                                                                                   
  • Confidence: High                                                                                                                                                                                            
                                                                                                                                                                                                                
  Canvas OOM during Image Compression                                                                                                                                                                           
                                                                                                                                                                                                                
  • Severity: High                                                                                                                                                                                              
  • Evidence: Image handling logic.                                                                                                                                                                             
  • Impact: The app crashes immediately upon the user selecting a photo.                                                                                                                                        
  • Why this fails in production: Modern phones take 12MP-48MP photos. Loading a 10MB JPEG into an  Image  object and drawing it to a Canvas expands it into an uncompressed bitmap in RAM. On budget Android   
  devices or older iPhones, doing this while the React app is running can exceed memory limits and crash the tab.                                                                                               
  • Minimal fix: Use modern web APIs like  createImageBitmap  with the  resizeWidth  option, which decodes and resizes the image asynchronously in a worker-friendly way without creating a massive intermediate
  canvas in the main thread.                                                                                                                                                                                    
  • Confidence: Medium                                                                                                                                                                                          
                                                                                                                                                                                                                
  ### Medium issues                                                                                                                                                                                             
                                                                                                                                                                                                                
  No Data Portability / Fallback Export                                                                                                                                                                         
                                                                                                                                                                                                                
  • Severity: Medium                                                                                                                                                                                            
  • Evidence: Only PDF export is implemented.                                                                                                                                                                   
  • Impact: If the PDF generation fails for any unforeseen reason, the user's data is trapped in IndexedDB.                                                                                                     
  • Why this fails in production: Client-side PDF generation is inherently fragile. If a user encounters an edge case where it hangs, they have no way to retrieve their inspection data to show the dealer.    
  • Minimal fix: Add a secondary "Export Raw Data" button that downloads a JSON file containing the checklist state and the base64 images, or a ZIP file containing the images and a text summary.              
  • Confidence: High                                                                                                                                                                                            
                                                                                                                                                                                                                
  ### Architecture risks                                                                                                                                                                                        
                                                                                                                                                                                                                
  • Monolithic State Storage: Serializing the entire  AppState  (including all base64 images) into a single IndexedDB key means the browser must serialize/deserialize megabytes of data on every state change. 
  This will cause UI stutter (jank) on lower-end devices. Images should be stored in IDB as individual keys (or Blobs), and the  AppState  should only store references (keys) to those images.                 
  • Ephemeral Storage Volatility: Browsers can and will clear IndexedDB without warning if the device storage is full. If a user does a PDI on Tuesday and returns to the dealer on Thursday to finalize, the   
  data might be gone.                                                                                                                                                                                           
                                                                                                                                                                                                                
  ### Production readiness gaps                                                                                                                                                                                 
                                                                                                                                                                                                                
  • Missing Error Boundaries: If a render fails (e.g., malformed state from IDB), the user might see a blank white screen (though  ErrorBoundary  exists in  App.tsx , we need to ensure it gracefully handles  
  missing/corrupt data).                                                                                                                                                                                        
  • Lack of Storage Quota Monitoring: The app should proactively check  navigator.storage.estimate()  on boot to warn the user if they have critically low space before they begin a 45-minute inspection.      
                                                                                                                                                                                                                
  ### Priority fix plan                                                                                                                                                                                         
                                                                                                                                                                                                                
  1. Refactor State Storage: Separate the checklist state from the image data in IndexedDB. Store images as independent Blobs mapped by ID, rather than inline base64 strings in a massive JSON object.         
  2. Redesign PDF Generation: Ditch  html2canvas  for the full document. Use  jspdf  native APIs ( doc.text ,  doc.addImage ) to programmatically build the PDF page by page to avoid canvas dimension limits.  
  3. Implement Resilient Image Compression: Swap canvas-based compression for  createImageBitmap({ resizeWidth: 1080 })  to prevent OOM crashes during capture.                                                 
  4. Add Fallback Export: Implement a "Download Data (ZIP)" option as an escape hatch in case PDF generation fails.                                                                                             
  5. Implement IDB Error Handling: Add explicit try/catch blocks for  QuotaExceededError  with user-facing alerts.                                                                                              

  ### Verdict  

     Ship only after targeted fixes
